# 面板配置：一个型号文件是怎么变成硬件的

> 面板配置文件里的每一个值，要么是**控制器的固有事实**，要么是**玻璃的属性**，
> 要么是**这块板的接线**。搞混这三者，症状会指向错误的方向——红色蓝色反了你会去查字节序，
> 图像转了 90° 你会去查旋转参数，其实都在这三类里。

## TL;DR

- **`TFT_MODEL_*` 选的是"初始化序列变体"，不是屏的厂商。** 同一个标志在不同玻璃上含义可能相反。
- **红蓝顺序是玻璃属性**，走 `TFT_BGR`（MADCTL bit 3）；**字节序**才是 `TFT_COLOR_16_SWAP`。两者症状不同，见下表。
- **GRAM 偏移是玻璃属性**，走 `TFT_X_OFFS` / `TFT_Y_OFFS`。设错只会在边缘留一条未刷到的像素，不会破坏画面。
- ST7735 驱动**没有 `set_dir()`**，所以 `TFT_ROTATION` 无法补偿 MADCTL——朝向只能在初始化序列里定。

## 症状对照表（先查这张表再改代码）

| 现象 | 大概率原因 | 旋钮 |
| --- | --- | --- |
| 红蓝互换，其它颜色都对 | MADCTL bit 3（BGR）与玻璃不符 | `TFT_BGR` |
| 每个颜色都像"另一个颜色"，伴随机理图案改变 | 字节序 | `TFT_COLOR_16_SWAP` |
| 整个画面转了 90° | MADCTL bit 5（轴交换） | `TFT_MADCTL_MV`（默认值随序列） |
| 画面正常但顶部/左侧有一条未刷到的边 | GRAM 偏移 | `TFT_X_OFFS` / `TFT_Y_OFFS` |
| 满屏噪点但规律 | 通常**是对的**——量测用的填充图样 | — |

**判定工具：彩条，不是噪点。** 8 条竖彩条能一次区分"控制器错 / 轴序错 / 偏移错 / 红蓝反"，
而噪点图样只能告诉你"有数据到了"。`examples/bench_screen_fps.c` 会留下这 8 条彩条。

## 三类东西

### 控制器的固有事实 → 跟驱动走

初始化寄存器序列、COLMOD、GRAM 尺寸。**新增控制器时才动**，正常加一个屏不需要改驱动。

### 玻璃的属性 → 配置变量

同一颗控制器在不同玻璃上的差异，全部应是配置变量：

| 属性 | 变量 | 备注 |
| --- | --- | --- |
| 红蓝顺序 | `TFT_BGR` | 曾写死在 ST7735 驱动里，导致换一块玻璃就红蓝互换 |
| GRAM 偏移 | `TFT_X_OFFS`、`TFT_Y_OFFS` | ST7735 的 GRAM 常比可视区大 |
| 字节序 | `TFT_COLOR_16_SWAP` | 8 位总线上 RGB565 先发高字节 |
| 初始化变体 | `TFT_MODEL_*` | **名字有误导性**，见下 |
| 轴交换（横/纵） | `TFT_MADCTL_MV` | MADCTL bit 5。默认值由初始化序列给（GENERIC=1、MD144=0），设了就以你为准 |
| 分辨率、朝向 | `TFT_HOR_RES`、`TFT_VER_RES`、`TFT_ROTATION` | 朝向还影响触摸 |

### 这块板的接线 → 配置变量

引脚、总线类型、总线时钟、背光极性。这些**一板一样**，第 4 条铁律（总线时钟是编译期常量）在这里生效。

## `TFT_MODEL_*` 这个名字是坑

它的实际语义是"**用哪一支初始化序列**"。以 ST7735 为例，两支只差 MADCTL 的一个位：

```c
// TFT_MODEL_GENERIC        0x36 = 0xE0  (MY|MX|MV)   MV=1 → 行列交换 → 横向玻璃
// TFT_MODEL_MD144_SPI_V04  0x36 = 0xC8  (MY|MX)      MV=0 → 纵向玻璃
```

一块 128×160 的**纵向**屏用 GENERIC 那支，画面就会转 90°，而且窗口被按旋转后的朝向解释、
**部分行保留旧内容**（不是全屏都错，容易误判成撕裂或总线问题）。

反过来 `fpc-zh096g1321`（160×80）用 GENERIC 是对的——因为那块玻璃本来就是横向的。
**同一个标志在两块玻璃上要求相反**，这就是它容易出事的地方。

## 朝向只有一处能定

ST7735 驱动没有 `set_dir()`，`TFT_ROTATION` 只影响 CMake 换算出的几何与触摸方向，
**不会改变面板的扫描方向**。所以：

- 对**有** `set_dir()` 的驱动（当前只有 `tft_1p5623.c`、`tft_ili9488.c`），旋转会成对生效；
- 对**没有**的，`TFT_ROTATION != 0` 会让几何已经转了、面板没转 —— 画面被切。
  改朝向要连初始化序列一起改。

> 这是本库已知的架构缺口，不是某个型号的问题。

## 复现 / 调试

```bash
# 用彩条验证一块新屏（会留下 8 条竖彩条，同时打印带宽）
cmake -S examples -B build -DPICO_BOARD=pico2 -DPUD_CONFIG=<型号> \
      -DPUD_EXAMPLE_STDIO_USB=1      # 板子 UART 没接出来时用 USB 日志
cmake --build build -j8
picotool load -f -x build/bench_screen_fps.elf
```

例子里对同一块缓冲区**连刷两次**，那是 `TFT_COLOR_16_SWAP` 路径的回归测试：
如果驱动把调用方的缓冲区改了，第二次的颜色就会翻转。
